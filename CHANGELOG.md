# Changelog

This file records source-workspace increments. It is not a published-release announcement; local installation status belongs to the migration/acceptance records.

## Unreleased

### Current pending source work

- `/paths` is easier to read:
  - It is gold and full width, so the transcript no longer shows through at the sides.
  - Each message row drops the repeated "you" and shortens long file paths to their last part.
  - A day line ("Today", "Yesterday", a date) separates days.
  - The selected row is highlighted rather than dimmed.
  - The reply preview is rendered, not raw markdown.

- Every frame is thin and rounded again. Bold edges never matched the thin rounded corners (Unicode has no bold rounded corners), and terminals such as Rex draw both weights alike. `weight: "heavy"` still marks attention; it is shown with color and bold labels. Tool rows use a thin rail.

- `/btw` keys reworked so typing never triggers an action: Tab switches between asking and reading. Reading scrolls with arrows, PgUp/PgDn and the mouse wheel, and shows how much is above and below. `n` starts a new aside and `r` renames (it was `n`). Renaming saves on Enter, Tab or an arrow, and the "Named" note clears itself.
- `/btw` answers can be stopped (Esc or `s`), each aside shows its own "answering" status, and copy, send and fork use the answer in view. Stopped and failed answers are kept on reload. Switching session or path stops an unfinished side answer instead of saving it onto the new branch.

- Press Escape twice on an empty, idle Composer to open `/paths` (Pi's own double-Escape tree stays reachable with `/tree`).
- Finished tasks in the dock are struck through. The `/tasks` panel uses the panel placement's bold rounded frame, and the `/egregore` Tasks preview shows the real checklist.
- Works on Pi 1.6: border-free copying reads Pi 1.6's new container layout as well as 1.5's.
- The Ask README is shorter and describes `consult`, answering, keys and the queue as they are now.

- Frame now names four standard placements: `input` (takes the composer's place), `panel` (centered over the transcript), `dock` (above the composer) and `transcript`. Each has a line weight and a height budget (`framePlacement`). `/btw` is an input surface, so it no longer half covers the composer, and `/paths` is a panel. The Frame and root READMEs explain how to build a new surface.
- A sense of time: your message frame shows "2 h later" when you come back after a pause; resuming a session idle for over two hours shows one line, "Back after 3 days · you last asked: …", until your next run; a running tool row counts up ("running 12s"); the composer marker pulses with streaming text and plays one short settle into ✓ when a run succeeds.

- New `/btw` (also `/aside`): ask a side question about the session without adding to the chat. It streams in a teal panel, sees the conversation including a reply still being written, and has no tools. Follow-ups continue the thread, and threads can be named (`n`) and reopened with `/btw @name`. `c` copies, `i` sends the answer to the chat, `f` forks a branch that continues with tools. Threads are saved as session entries outside the model's context.
- New `/paths`: your messages down the left, `⑂N` where you rewound, the other paths one step away, a preview of the chosen message, labels as bookmarks and search. Enter goes there; `e` rewinds and puts the message back to edit. The Composer title shows `⑂ 2/3` while you are on one of several paths.
- Frame's heavy weight keeps rounded corners and bolds only the edges, so every frame stays rounded.

- The Tasks dock is now the checklist itself, in plan order around the work in progress: the task just finished, the active task, what follows, then earlier tasks not yet started. `✓ ◉ ! ○ –` glyphs, `· paused`, `· after …` for dependencies, phase headers with progress, and `+ N more`. When space is short, both hosts keep questions and the active task and drop headers and finished work first (`DockRow.kind`, shared `prioritizeDock`). The native dock now shows its overflow count.
- Questions inside Tasks are simpler. Questions waiting on you lead the dock as `?` rows. An answer is resolved once it reaches the agent as a message, so there is no "apply" step, and "delivery pending" and "agent follow-up" are gone. `question_queue` offers post, list, withdraw and replace, with three short guidelines, and its results are rows on the tool rail.
- `/tasks` advertises `new`, `add` and `history`; the other subcommands still work when typed, and the panel keys cover them. The `tasks` tool no longer exposes `revision`, `blockerOwner` or `unblockWhen`; existing records with them still load. The tool description and context reminders are rewritten in a few plain sentences, and the Tasks README is rewritten as a short guide.

- Ask's two tools are now one: `consult` asks one to four questions (one opens the focused form, several open the form with Review). Its guidance is short and names when to ask: unclear goal or scope, forks between approaches, taste and naming, anything hard to undo, and when sharing a plan. It replaces a dozen lines that talked the model out of asking. The old `ask_user_question` and `ask_questions` stay registered but hidden so earlier sessions still render.
- New setting `/egregore` → Ask → Question frame → **How often to ask**: only when needed, balanced (default) or curious. It adds one guideline line per run.
- A single-choice question now answers with one Enter, and a custom "Something else" answer submits when entered. The multi-question form keeps select-then-continue, since Review confirms there.

- Tool calls are now one row each on a shared rail instead of a box per call: marker, name, target and a quiet detail (line count, diff counts, `exit N`), with error and live-output notes beneath. Tasks and Ask calls use the same rows (`Done`, `Started`, `Asked` with your answer). Expanding a row still opens the full card. The grouped file-tool box is retired.
- Bolder lines (`╭━╮┃`, still rounded) now mark what wants attention: the Composer, a question and the live Tasks dock. History stays light. Frame gains `weight` and a `toolRows` primitive.
- Question dialog: the footer no longer repeats "+ Note" (the row by the options stays), Regenerate moved to F2 More, "Write your own answer." and a lone "1 of 1" are gone, and the discard hint reads "Esc Discard note".
- Fixed the settings preview reporting a clipped Ask element as visible on short terminals.

- Renamed the remaining Pi Workspace names to Egregore. `/workspace` is gone; use `/egregore`. Source files `workspace-*.ts` are now `runtime.ts` and `settings-*.ts`, runtime IDs use `pi-egregore:` (including the `pi-egregore:interaction:v1` event), and the test host override is `PI_EGREGORE_HOST_MODULES`. The legacy `pi-workspace.json` is still read as a fallback.

- Removed Quests: the `quests` tool, `/quests`, its journal code, tests and design docs. Existing journal data in `~/.pi/agent/quests/` is left untouched.

- Removed session activity (`/activity` and the General → Session updates settings). It was a feed of Quests updates and would only repeat the Tasks dock. Saved `sessionActivity` and `activityColor` values are ignored.

- Moved the deploy job into `ops/sync` and renamed it Egregore sync. Each release now lists the commands it must provide in `package.json` → `egregoreSync.requiredCommands`, so removing or renaming a command no longer needs edits on every machine. `ops/sync/install.py` migrates a machine from `pi-workspace-sync`.

- Extended fullscreen border-free copying to the Composer, including the existing native/pi-vim editor and fallback editor. Copy excludes recorded rails and layout padding, preserves literal border characters, indentation and internal blank lines, and leaves completion rows and unsupported/stale layouts native. No clipboard backend or input behavior changes.

- Simplified Tasks to a checklist after a small local model looped on the mandatory library-revision error: every write had to echo the current revision, `create` had to reconcile pre-written requirement IDs, and an uncovered-request ledger blocked plan closure. The requirement ledger, its coverage states, the `requirements` tool op, the question gates and the one-pass `agent_before_settle` reconciliation continuation are removed. Writes now accept `revision` as an optional snapshot assertion (omitted applies to live state; stale is rejected), plans close when every task is done or cancelled, and unresolved questions remain visible attention without gating task transitions. `PlanBook` payload version 4 keeps the `pi-tasks:plans-v2` entry key and migrates v2/v3 by discarding retired `requirements` records. `requirements.ts` and `reconciliation.ts` are deleted; the panel's read-only Requests view and `V` key are gone.

- Fixed the framed-message row loss reported after a screenshot showed a user frame whose first wrapped line was blank with only the left rail painted: `sent-messages.ts` had moved the native `OSC 133;A` marker out of the removed blank top row and into the middle of the first content row, so a prompt-aware redraw treated that row as a prompt start and wiped it, and Pi's own start-anchored `scrollToPrompt` could never match it. Trimmed edge-row markers are now collected and prefixed to the frame's outermost rows (start on the top rail, `B`/`C` on the bottom rail) at column 0, keeping `OSC133_ZONE_PREFIX` able to strip them and every content row marker-free. User and assistant frames are covered across wide/narrow widths and both densities; wrapping, copy-frame offsets and mouse mapping are unchanged.

- Fixed Tasks' plan-creation retry loop: a missing `revision` error now returns the current library revision so one retry succeeds instead of sending the agent to `list`, and `create` accepts requirement records whose pre-written ids are exactly the sequential `r1`, `r2`, … it assigns (rejecting any other id, or a superseded disposition, with an actionable message). Previously a natural `create` with `r1`/`r2` ids failed with "Unknown requirement ID; read requirements first", which reading an empty new ledger could never resolve; the agent then dropped the ids and lost the revision. Guidance now says to omit ids on create. Schema, storage and atomicity are unchanged.

- Fixed the Ask answer panel's overflow after a screenshot review showed a clipped question deleting the choice list: the panel now uses the screen's own height (`rows - 2`, overlay-capped at its `maxHeight`) instead of a fixed 26 rows, allocates the question and choices from measured chrome in one pass, and keeps the question as the first region with its own `↑/↓ N more lines · Alt+↑/↓` window. Choices render in full when they fit, otherwise the focused choice keeps its description, `Why:` and `Caveat:` while the rest compress to one label row plus their suggestion badge. Every counted marker reserves its own row and never overwrites content, so a `Caveat:` can no longer appear above an option that does not own it. The remaining limits — a single choice block taller than the option region, and a pinned **Something else…** editor on the smallest panels — are counted and named in the package README.

- Added Quests' contextual possibility presentation: explicit green `Possibility · Title` Markdown rendering through the optional public host transformer, a compact unframed presentation alternative, counted journal directions, sourced keep/explore/make intent, and retry-safe offer/link capture. Legacy records and plain Markdown remain readable; no side conversation, Obsidian integration, new activity panel or background run is introduced.

- Kept the requested response primary in Tasks' completion review: the mandatory Where next suggestion reply is gone, Deepen/Connect are optional lenses, and a record-only reconciliation finishes quietly. This changes guidance only; checkpoint eligibility, guards and schemas are unchanged.

- Added pursuit continuity: immutable source-linked understanding/uncertainty/decision/artifact/observation records with explicit corrections and idempotent keys; current-branch Tasks/Ask snapshot synchronization; bounded read-only resume orientation and branch-local focus through existing before-run guidance. Answer notes and reported consequences remain inspectable; syncing never applies answers, completes tasks or grants authorization.
- Replaced `/questions`' generic selector with a bounded inbox using Ask's shared frame, appearance, pin controls and native selection. Corrected the posted-answer validator to use the normal form's one-based option identity; real-form inbox → choice → note → Review → Submit regressions cover the formerly rejected valid selection.

- Added read-only `quests present`: a shared Where next handoff with jade Deepen/gold Connect labels, value/first move/From source, explicit journal versus conversation-only state, native expansion and plain-text fallback. Aligned Tasks and Quests handoff guidance without adding a continuation hook.
- Corrected the compact Tasks dock after screenshot review exposed dense blocker rows: actual answerable questions now lead with their answer route; agent activity, delivery/application and external waiting have concise distinct groups. Updated standalone fallback and settings samples; task and approval state are unchanged.

- Coordinated Quests, Tasks and Ask around a clearer collaboration flow: counted quest disclosures and separate current next moves; Tasks tree grouping, dependency context and optional blocker responsibility/release conditions; attention that distinguishes user input from delivery and agent follow-up. Tool guidance connects applying answers to reassessing work without automatic completion or background monitoring. Legacy records remain readable and browsing stays read-only.

- Renamed the product and private root package to Pi Egregore, with a philosophy of sustained human–agent thought partnership. The UI entry is `extensions/pi-egregore`; `/egregore` is primary with `/workspace` retained as an alias. Appearance uses `pi-egregore.json` with read-only Workspace/footer fallbacks shared by Ask. Historical protocol IDs and stored session records remain compatible; local path migration is documented separately.
- Fixed quest-detail clipping by mounting a bounded overlay instead of budgeting the full terminal height inside the editor area. Height/resize regressions check the bottom rail and action reachability; tiny terminals have an unframed fallback. The separate journal-density audit proposes progressive disclosure without claiming that redesign is implemented.

- Added cross-platform Egregore notifications: React Bits Sound Lab Pluck on successful final settlement, and quieter Hint once per blocking Ask call. macOS uses `afplay`, Windows uses PowerShell with checked WinMM `PlaySoundW`, and Linux selects available PipeWire/PulseAudio/ALSA players without masking device failures. Windows rejects a FALSE native result and forbids default-beep fallback, replacing the initial SoundPlayer path that could hide backend failures. `/sounds` exposes session-only mute and preview controls; errors, late cancellation, passive browsing and noninteractive runs remain silent. Bundled portable 16-bit PCM WAVs carry original export and conversion provenance plus the upstream MIT + Commons Clause notice. Playback adds no npm dependency; Linux requires an installed player and audio output. Native Windows regressions cover accepted playback and rejected missing assets in the existing OS CI matrix.

- Centred Composer's single static ember mark in the five cells the scenes fill. It previously sat in the last of those cells, so the idle `○` beside `What's next?` hugged the label and left the marker block visually empty on its left; idle, waiting, finished, failed and stopped marks now share the working scenes' centre axis, and labels still begin in the same column.

- Replaced Composer's single comet with the five-scene living ember the contract documents: figure-eight for thinking, a four-lane conveyor for writing, twin counter-orbits for tools, corner collapse for compaction and a serpentine trail for generic working. One `dot()` writer snaps to the ten-by-four braille grid, drops off-canvas points and records per-cell heat, so rendering stays deterministic from elapsed run time with no timer, randomness or state write; static marks right-align inside the same five cells so moving and static labels share one column.

- Made the dictation suite portable after a Windows report and recorded the rule in `AGENTS.md`: `npm test` runs on the three-OS CI matrix, so tests must not hardcode an existing POSIX path (`/bin/sh` → `process.execPath`), a separator-bearing expectation (`join` in both the value and the expected string), or a bare path passed to native `import()` (`pathToFileURL`). The reported two failures hid three more, because the `/bin/sh` assertion aborted its test before later assertions ran; the guidance now names that masking and keeps independent platform-sensitive assertions separable.

- Added a project-local `/update` command in `.pi/prompts/update.md`: it records a baseline, updates the Pi host, reads the changelog and declaration diff against the previous release, reviews every host import and guarded native internal, refreshes the lockfile host and recorded version baseline, then runs the full pipeline plus an isolated cold load. Only `.pi/prompts/` and `.pi/README.md` are un-ignored; other `.pi` state stays out of Git.

- Added Composer microphone dictation as a new `dictation.ts` module: the fullscreen bottom rail carries a mic that captures through one `ffmpeg` child (avfoundation/dshow/PulseAudio or ALSA, 16 kHz mono, five-minute cap), shows `REC <n>s`, and inserts the local `whisper-cli` transcript at the editor cursor on the second click; `/dictate` is the keyboard path where pointer clicks cannot arrive or the rail is under 40 columns. The first use without a model asks once before a `.part`-streamed `ggml-base.en.bin` download (142 MB) whose SHA-256 is checked against the digest Hugging Face announces on its redirect; declining or failing writes nothing. Missing tools show `mic !` with a platform-specific hint. Recording is stopped with an interrupt because ffmpeg only reads `q` on a real terminal. Every child's stdio stream carries an error listener and spawn failures reject the start with the errno and the offending path, because an unhandled `error` event on a child or its stdin would otherwise take down the whole Pi process. Setup cancelled mid-confirmation or mid-download stops there: every continuation, progress callback and rejection is generation-guarded, so a stale download can neither start a recording nor reset a newer one, and a rejecting dialog is reported rather than escaping as an unhandled rejection. No npm dependency, no preference file, no `/workspace` room: `pi-composer.json` and `pi-workspace.json` are untouched, and neither editor wrapper lets the rail click take keyboard focus. Windows/Linux capture argv, device-hint classification and the download's integrity path are unit-tested; their real device paths and a spoken microphone pass remain manual.
- Reworked the Ask panel's controls: the keybind bar names the note action in every mode (**+ Note** for choices, **Tab Note** for free text), **Esc Close** and note-discard hints use the error tone, Escape is one deterministic close that shows a red **⚠ Discard N answers and M notes and close?** confirmation (empty forms close at once; Escape no longer clears a staged answer, which is now **Ctrl+C**), F2 More lists **Discard and close** and **Clear selection**, a session-only **Pinned** corner label collapses the panel to a one-line bottom bar that keeps the question, progress and dismiss visible while the transcript scrolls (posted overlays anchor bottom-center), and **Something else…** keeps a three-row capped editor pinned below a scrollable window of the earlier options with **Alt+Up/Down**. Ask previews still show only title/progress/body/hint hits.
- Added Windows/Linux/macOS CI at Node.js 22.23.2, npm 10.9.8 and Pi 1.3.0, plus a non-admin Windows Git Bash installation and interactive smoke-test guide. Loader fixtures use Windows junctions, path filters accept both separators, captures use unique OS temp directories, and only the unrepresentable newline-filename filesystem case is skipped on Windows. Footer shutdown waits for Git child handles to close; cleanup uses bounded retries. Packed-suite tests invoke npm/Pi JavaScript entry points without Windows shell-shim assumptions.
- Diagnosed the five Vim undo failures as pi-vim 0.14.2's hard-coded Ctrl+- dispatch versus Pi's Windows Ctrl+Z default. Documented an explicit user-keybinding alias and applied it in integration fixtures without weakening preservation assertions; a separate undecorated-editor regression reproduces the upstream failure and verifies recovery using the same history. No live keybindings or upstream Vim source are modified.

Ask preserves renderer-owned fake-cursor markers and strips injected markers; cursor regressions cover software/hardware modes. Workspace fixtures strip zero-width cursor wrappers and finish native Codemode partial-result lifecycles so elapsed-time intervals cannot keep tests alive. Narrowed the regeneration test's action union for TypeScript.

The suite loads `extensions/pi-workspace/index.ts`; `/home` is no longer registered. Legacy preference/session/protocol identifiers remain readable without an automatic live migration.

Regression, strict type, package and isolated real-Pi transition evidence is recorded in `docs/ACCEPTANCE.md`.
